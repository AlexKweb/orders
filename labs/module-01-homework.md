## Задача 1. Пул воркеров

Напишите функцию, которая выполняет список задач, но не больше `n`
одновременно:

```go
func Run(ctx context.Context, n int, jobs []func(context.Context) error) error
```

Что она должна делать:

- одновременно работает не больше `n` задач;
- если `ctx` отменили, новые задачи не запускаются, а `Run` возвращает
  `ctx.Err()`;
- если какие-то задачи вернули ошибки, `Run` возвращает их все через
  `errors.Join`;
- к моменту, когда `Run` вернулся, все запущенные ей горутины завершились.

Тесты, которые нужны:

1. **Лимит.** Задачи считают, сколько их работает одновременно, и тест
   проверяет, что больше `n` не было.
2. **Отмена.** Отменяем контекст посреди работы и проверяем, что `Run`
   вернул `context.Canceled` и не запустил оставшиеся задачи.

И один бенчмарк: задача, которая ждёт 1 мс (`time.Sleep`), прогон при
`n` = 1, 4, 16 и 64. Результаты положите в описание PR и одной-двумя
фразами объясните, что видите.

## Задача 2. Починить гонки

Скопируйте код в `labs/stats/stats.go`. В одном потоке он работает,
а при параллельных вызовах — нет.

```go
// Package stats считает обработанные заказы.
package stats

import "sync"

// Stats — статистика по заказам. Создаётся через New.
type Stats struct {
	mu       sync.Mutex
	total    int64
	byStatus map[string]int64
}

// New создаёт пустую статистику.
func New() *Stats {
	return &Stats{byStatus: make(map[string]int64)}
}

// Record учитывает обработанный заказ.
func (s *Stats) Record(status string) {
	s.mu.Lock()
	s.byStatus[status]++
	s.mu.Unlock()

	s.total++
}

// Total возвращает число учтённых заказов.
func (s *Stats) Total() int64 {
	return s.total
}

// ByStatus возвращает число заказов в статусе status.
func (s *Stats) ByStatus(status string) int64 {
	s.mu.Lock()
	defer s.mu.Unlock()
	return s.byStatus[status]
}
```

Что сделать:

1. Напишите тест, в котором несколько горутин параллельно вызывают
   `Record`, а в конце проверяется `Total()`. Убедитесь, что под `-race`
   он падает.
2. Почините код, чтобы тест проходил под `make race`.
3. В описании PR одной строкой на каждую: какие гонки нашли и как починили.

## Задача 3. TLS на `orders`

Сервис должен уметь отвечать по HTTPS.

- Пути к сертификату и ключу берутся из переменных окружения
  `ORDERS_TLS_CERT_FILE` и `ORDERS_TLS_KEY_FILE`. Заданы обе — сервис
  работает по HTTPS, не задана ни одна — по HTTP, как раньше.
- Это покрыто тестом в `internal/config`.
- Сертификат и ключ не попадают в репозиторий: добавьте их в `.gitignore`,
  а в `README.md` напишите, как их получить.

Проще всего получить сертификат так: `mkcert -install && mkcert localhost`.
Со стороны Go хватит `ListenAndServeTLS(certFile, keyFile)`.

Потом запустите сервис и выполните:

```bash
curl -v https://localhost:8443/healthz
openssl s_client -connect localhost:8443 </dev/null
```

В описании PR ответьте на два вопроса:

- какая версия TLS и какой шифр выбраны;
- что будет, если обратиться к сервису с машины, где не выполнен
  `mkcert -install`, и почему.

## Подсказки

- Чтобы дождаться всех горутин, удобно использовать `sync.WaitGroup`.
- Ограничить число одновременных задач проще всего буферизированным
  каналом на `n` мест: занял место — работаешь, закончил — освободил.
- Счётчик одновременных задач в тесте — `atomic.Int64`.
- Не используйте `time.Sleep`, чтобы «дождаться» горутин в тестах: такие
  тесты то проходят, то падают.
